# Özkurt Hukuk — Büro Yönetim Sistemi

Bu dosya projenin tek bilgi kaynağıdır. Claude Code ve Codex aynı kuralları buradan okur (`AGENTS.md` buraya yönlendirir). Oturum başında okuyun, iş bitince güncelleyin. Değer değil, yalnızca env değişkeni **adları** yazılır.

## Amaç ve kapsam
Hukuk bürosu için görev, dosya, müvekkil ve muhasebe takibi. Ofis içi ağda 5-6 PC tarayıcıdan kullanır. Sunucu, ofisteki bir Windows PC'dir (mesai boyunca açık, akşam kapanır). İstemci PC'lere hiçbir şey kurulmaz.

Production'da git/Docker/geliştirici aracı yoktur: kurulum `Setup.exe` (Inno Setup) ile yapılır, uygulama Windows servisi olarak çalışır (WinSW + Waitress, ayrıca PostgreSQL servisi).

## Yığın
Python 3.13, Django 5.2 LTS, PostgreSQL 17, HTMX 2 + Alpine.js 3, Bootstrap 5.3. Tüm frontend kütüphaneleri `static/vendor/` altında repodadır; CDN kullanılmaz (internetsiz çalışmalı). Bağımlılık yönetimi `uv`.

## Komutlar (geliştirme)
```
docker compose -f docker-compose.dev.yml up -d   # dev PostgreSQL, host portu 5434
uv sync                                          # bağımlılıklar
uv run python manage.py migrate
uv run python manage.py setup_office_users --pin <PIN>   # ofis kullanıcıları (PIN repoya yazılmaz)
uv run python manage.py seed_dev                 # 2 küçük örnek kayıt (kullanıcılar önceden olmalı)
uv run python manage.py seed_demo                # deneme için uydurma kapsamlı veri (yalnızca DEBUG; tekrar çalıştırılırsa eklemez)
uv run python manage.py runserver
uv run pytest                                    # testler (dev DB'de test_ veritabanı açar)
uv run ruff check .
uv run ruff format --check .
```
Dev ayarları `config/settings/dev.py`, varsayılan DB bağlantısı dev compose'daki DB'dir. Dev'de statik dosyaları WhiteNoise sunar (`whitenoise.runserver_nostatic`, `max-age=0`); CSS/JS değişikliği için Ctrl+F5 gerekmez. Henüz kurulu ofis sürümü yoktur; proje geliştirme aşamasındadır. 5433 portu bu makinede başka bir projede dolu olduğu için 5434 kullanılır.

Windows makinesindeki geliştirme veritabanında gerçek ofis verileri vardır; sıfırlamayın, örnek veriyle karıştırmayın ve testlerde kullanmayın. Kaynak dosyalar `veritabanı entegrasyon/` altındadır, git'e girmez. Vekalet listesi aktarımı kısmen tamamlanmıştır; güncel bekleyenler Ayarlar > Vekalet listesini incele ekranındadır. `on-inceleme-listesi.txt` önceki durumun dökümüdür, vekalet satırlarında güncel sayılmaz. İcra listesi ve `KAPALI1` sayfası henüz aktarılmadı; önce aktarılan 20 arşiv dosyasındaki karşı taraflar şimdilik dosya notundadır. Açık ve kapalı fiziksel arşivler ayrıdır; aktarılan klasörlerde `Açık` / `Kapalı` öneki bu ayrımı korur. Aktarım öncesi yerel veritabanı kopyaları aynı PostgreSQL sunucusunda `ozkurt_before_poa_review_20261102`, `ozkurt_before_poa_auto_20261102` ve `ozkurt_before_poa_shared_20261102` adlarıyla tutulur; bunlar ayrı bir cihazdaki yedek değildir.

`seed_demo` yalnızca uydurma veri üretir; güncel görev türleri, farklı görev aşamaları, kapalı örnek görevlerin puanları ve iki örnek haciz içerir. Fiziki arşiv alanlarını ayrı tutar; örnekler arasında kapalı 1 / 58, icra 15 / 8 ve 4 / 85 vardır. Örnek kapalı görevler, gerçek görev kapatma işleminin henüz uygulanmadığı gerçeğini değiştirmez.

## Env değişkenleri (production)
`DJANGO_SETTINGS_MODULE=config.settings.prod`, `DJANGO_SECRET_KEY`, `DATABASE_URL`, `DJANGO_ALLOWED_HOSTS`, `MEDIA_ROOT`, `STATIC_ROOT`, `LOG_FILE`. `BACKUP_PASSWORD`, `BACKUP_DIR`, `PG_DUMP`, `PG_RESTORE`, `BACKUP_DATABASE_URL`. Şablon: `.env.example`.

## Mimari
- `config/settings/{base,dev,test,prod}.py`, `config/urls.py`.
- `apps/core`: ortak model (`TimeStampedModel`), validator'lar (TCKN, VKN, IBAN), Türkçe metin yardımcıları (`fold`, `tr_lower`), form mixin'i, template tag'leri (`tl` para formatı, `sort_link`, `query_with`), `seed_dev`.
- `apps/accounts`: özel `User` (rol: admin/lawyer/intern, unvan, giriş ekranı sırası, tema, sayfa boyutu). Hatalı PIN denemesinde kilit yoktur (kullanıcı kararı; `django-axes` kaldırıldı). Kontrolcü `User.supervisor` (Ayarlar > Kullanıcılar; her rol için atanabilir): görev formunda sorumlu seçilince kontrolcü olarak onun kontrolcüsü otomatik dolar (değiştirilebilir; `TaskForm.supervisor_map`); stajyerin kontrolcüsü olan avukat müvekkil/dosya formunda seçilince bağlı stajyer de otomatik dolar (`clients.views.intern_by_lawyer`).
- Giriş: kullanıcı adı/şifre yok. Giriş ekranında aktif kullanıcıların kartları listelenir, kullanıcı kartına tıklayıp PIN girer. PIN, Django parolası olarak hash'li saklanır (`set_password`); `PinValidator` tam 4 rakam ister; giriş ekranı 4. rakamda formu otomatik gönderir (Enter gerekmez). Kullanıcı PIN'ini Ayarlar > PIN değiştir'den değiştirir. Yönetici `/yonetim/` panelinden başkasının PIN'ini sıfırlayabilir.
- Ofis kullanıcıları `apps/accounts/management/commands/setup_office_users.py` içindeki listedir. Yeni kullanıcı eklemek için listeyi güncelleyip komutu çalıştırın; komut mevcut PIN'leri yalnızca `--reset-pin` ile değiştirir. Unvan ≠ rol: "Koordinatör Avukat" rolü `lawyer`, "Yönetici Avukat" rolü `admin`.
- `apps/office`: `OfficeSettings` (singleton, `OfficeSettings.load()`), `TaskType`, `Court` (merci listesi).
- `apps/clients`: `Client` (gerçek/tüzel), iletişim, IBAN, yetkili, vekalet (`PowerOfAttorney`), karşı taraf (`Party`). Çıkar çatışması kontrolü kullanıcı kararıyla kaldırıldı (müvekkil formu, dosyaya karşı taraf ekleme, Excel aktarımı). Müvekkil başına vekalet no `Client.poa_no` (V-121; fiziki vekalet klasöründeki yer); aynı vekaleti paylaşan müvekkiller aynı numarayı kullanabilir (`clients/0008`). Boşsa vekalet eklenince sıradaki numara ofis ayarı kilidiyle atanır. Müvekkilde aktif/pasif alanı yoktur. Avukatlık sözleşmesi (`RetainerAgreement`: tarih, isteğe bağlı müvekkilin kendi dosyası, isteğe bağlı vekalet ücreti, PDF; PDF müvekkil klasörünün `Sözleşmeler` altına kopyalanır, `media` yolu `clients/<id>/sozlesme/`): ücretli yeni sözleşme kaydedilince kullanıcı doğrudan muhasebe formuna (`tur=fee`, `tutar`, `dosya`, `aciklama` önerisiyle) yönlendirilir; Vazgeç ile müvekkil sayfasına döner, tutar kendiliğinden yazılmaz. İletişim, IBAN, yetkili (tüzel), vekalet ve sözleşme satırları yalnızca oluşturma/düzenleme ekranında eklenir/değiştirilir (`CLIENT_SUBRECORDS`, `client_formset`, `_formset.html`); mevcut satırı silme kutusu yalnızca yöneticide çıkar; birincil IBAN/iletişim (tür başına) tek kalır. Satırlar isteğe bağlıdır (`OptionalRowMixin`: boş satır yok sayılır, doldurulan satırda gerekli alanlar istenir; yıldız gösterilmez). İletişimde telefon, e-posta ve adres için eksik türlerin boş satırı hazır gelir (`DEFAULT_CONTACT_KINDS`). Form bölümleri `.form-masonry` ile geniş ekranda iki sütuna dengeli dağılır (sıra: tip+kimlik, sorumlular, yetkililer (tüzel), vekalet, iletişim, IBAN, notlar). Müvekkili silme düğmesi düzenleme ekranının alt çubuğundadır (yalnızca yönetici); `clients:delete` onay sayfası birlikte silinecek kayıtları sayılarıyla gösterir ve onay kutusu ister. `clients/services.delete_client` müvekkili dosyaları (ve dosyaya bağlı belge/duruşma/safahat/not), görevleri, muhasebe hareketleri ve randevularıyla birlikte siler; karşı taraflar ve diskteki yüklenmiş dosyalar kalır. Detay sayfası: başlıkta ad/unvan, V-no veya "Vekalet yok", açık/kapalı dosya sayısı; sekmeler Genel bilgiler (kimlik, sorumlular, vekaletler, iletişim, IBAN, yetkililer — iki sütun, salt okunur), Dosyalar (arama, durum, tür süzgeci ve sıralama; HTMX `clients:cases`, `_cases_table.html`), Muhasebe (herkese hareketler; bakiye ve yürüyen bakiye yalnızca yetkiliye; `#muhasebe`), Raporlar (müvekkile süzülmüş hesap ekstresi ve dosya son durumu; `client_reports`), Geçmiş.
- `apps/cases`: `Case` (9 tür, fiziki arşiv yeri klasör no + dosya no, türe göre etiketler `TYPE_LABELS`), `CaseParty`, `Document`, `Hearing` (kullanım dışı; eski kayıtlar korunur), `CaseEvent` (not + otomatik olaylar; yalnızca elle yazılan notlar Özet’in en altındaki Notlar bölümünde görünür, `case.notes` de aynı bölümde korunur; Geçmiş’teki "Notlar ve olaylar" ve özetin "Son hareketler" kartı kaldırılmıştır, otomatik olaylar veritabanında korunur), Tebligat özelliği kullanıcı kararıyla kaldırıldı (`Service` modeli silindi, `cases/0013`; ana sayfa, takvim, rapor ve müvekkil silme özetinde yeri yok). Not işlemleri `views_records.py`; eski duruşma işleyicileri uygulama adreslerine bağlı değildir. Taraflar sekmesi ve Özet taraflar bölümü dosya türünün yanlarına (davacı/davalı vb.) ayrılır; eski sıfatlar diğer türlerdeki yanından bulunur (`summary.party_groups`). Görevler sekmesi: üstte aktif (aktif + kontrolde), altta tamamlanan görevler, sıralama seçenekli. Dosya formunun Sil/Vazgeç/Kaydet düğmeleri sayfanın sağ üstündedir. Dosya detay sekmeleri: Özet, Taraflar, Safahat (bağlı dosyalar), Görevler, Belgeler, Muhasebe, Geçmiş. Özet verisi `summary.py`.
- `apps/tasks`: `Task` (tür, ad, dosya, müvekkil = dosyanın müvekkili, sorumlu, kontrolcü ≠ sorumlu, son gün, notlar), `TaskEvent` (geçmiş + yorumlar). Onay döngüsü ve yetkiler `services.py` (`ACTIONS`, `perform`, `available_actions`, `can_edit`). Görev formu müvekkile göre dosya süzer, dosya seçilince müvekkil ve varsayılan sorumlu (dosyanın stajyeri) / kontrolcü (dosyanın avukatı) dolar (`tasks:case_options`).
- `apps/accounting`: `LedgerEntry` (müvekkil zorunlu, dosya isteğe bağlı — dosyasız kayıt müvekkilin genel gelir/gideridir, dosya seçilirse müvekkiline ait olmalı; tür, tutar, tarih, açıklama, makbuz; iptal alanları). Türler: vekalet ücreti, masraf, tahsilat (müvekkilden), karşı taraftan tahsilat, müvekkile ödeme; mahsup kullanıcı kararıyla kaldırıldı (`accounting/0002`, eski mahsup kayıtları silindi). Bakiye ifadeleri `BALANCE_EXPR`/`DEBT_EXPR`/`CREDIT_EXPR`, `LedgerEntry.objects.balances()` (`debt`, `credit`, `balance`) ve `totals_by_kind()`. Ekstre `views.statement()` (yürüyen bakiye). Müvekkile ödeme karşı taraftan tahsilatı aşabilir (bakiye hesabı buna izin verir; kullanıcı kararı). Yetki `accounting/permissions.py`: herkes muhasebe kaydı görür, girer ve iptal eder (`can_view`, `can_edit`). Müvekkil bakiyesi, borçlu süzgeci, hesap ekstresi, muhasebe toplamları, ekstredeki bakiye sütunu ve finansal raporlar yalnızca yöneticiye ve `User.can_view_balances` işaretli kişilere görünür (`can_view_balances`; Ayarlar > Bakiye görme yetkisi). Rol bazlı muhasebe bayrakları kaldırıldı. Dosya sayfasından muhasebe kaydı eklenince/iptal edilince dosyanın Muhasebe sekmesine dönülür (`next` + `#t-muhasebe`).
- Müvekkil listesi `annotate_list_values()`: dosya sayısı, açık görev sayısı, cari bakiye alt sorgularla. Sütunlar: Vekalet (V-no, en başta), Müvekkil, Sorumlular, Dosya, Açık görev, Bakiye (yetkiliye; yeni formüle göre). Süzgeçler: tip, vekalet, avukat, stajyer, açık görev, borçlu (yetkiliye). Vekalet süzgeci, V-no veya ayrıntılı vekalet kaydından herhangi biri varsa vekalet var kabul eder. Sıralama açılır listesi `SORT_OPTIONS`; varsayılan `-poa` = vekalet no yeniden eskiye, numarası olmayanlar sonda ve kendi aralarında en yeni kayıt önce (`client_ordering`).
- Vekalet kaynak listesini inceleme (`/aktar/vekalet-listesi/`, yalnızca yönetici): sunucudaki `veritabanı entegrasyon/-LİSTE VEKALETNAME.xlsx` okunur; satırlar aranır, müvekkil eklenir veya mevcut müvekkille ilişkilendirilir. İşlenen satır ve kaynak dosya özeti `PowerOfAttorneyReview`, aynı satırdaki ek müvekkiller `PowerOfAttorneyReviewMember` ile izlenir; kaynak değişmişse işlem durur, eksik grup yeniden incelemeye düşer. İsim veya numara çakışmaları kullanıcıya gösterilir; mevcut kaydın numarası ilişkilendirme sırasında değiştirilmez. Varsayılan dağılım Nursu/Ecenur ve Göktürk/Ömer Faruk ekiplerinin mevcut sayılarına göre dengelenir. `poa_suggestions` ve `poa_groups` açık adları ve virgülle ayrılmış grupları kullanıcı talimatıyla eklemek için kullanılmıştır; çakışan veya ayrıştırılamayan satırlar bekler, otomatik eklenenler ekranda belirtilir. Çok kişili satırda tüm yeni müvekkiller aynı V-numarasını alır; müvekkil kartında kaynak notu ve paylaşılan satır gösterilir (`imports/0002-0005`).
- Belgeler ve ofis klasörü: `TaskDocument` (görev belgesi, sürüm zinciri `previous`/`version`/`is_current`; aktif görevde sorumlu, kontrolcü, yönetici yükler; yükleyen/yönetici siler, önceki sürüm güncel olur). `TaskType.requires_document` işaretli türde belge olmadan kontrole gönderilemez (Ayarlar > Görev türleri). Onayda `cases/documents.publish_task_documents()` güncel belgeleri dosyanın `Document` kayıtlarına kopyalar ve ofis klasörüne yazar (`<YYYY-MM-DD> <görev adı>.<uzantı>`). Dosya belgesi yüklemesi ve vekalet PDF'i de klasöre kopyalanır. Klasör mantığı `core/folders.py`: kök `OfficeSettings.documents_root` (Ayarlar > Belge klasörü, kaydederken yazma testi), yapı `<kök>\Müvekkiller\<Client.folder_name>\<Case.folder_name>` ve `<müvekkil>\Vekaletler`. Yeni klasörler müvekkilin ad-soyadı/unvanı ve dosyanın `display_name` değeriyle (kurum + numara, kurum/numara olmayan türlerde konu) adlandırılır. Windows için `/` yerine `-` kullanılır. Aynı ad veya sahipsiz bir klasör varsa `(2)`, `(3)` eklenir; mevcut klasöre yalnızca adından dolayı bağlanılmaz. Klasör oluşturma müvekkil ve ofis ayarı kilidiyle sıraya alınır. Kaydedilmiş adlar normal yüklemelerde korunur. `uv run python manage.py rename_document_folders` yalnızca önizler; `--apply` müvekkil/dosya klasörlerini ve Document/PowerOfAttorney/RetainerAgreement yollarını yeni düzene dönüştürür. Önce bütün yollar denetlenir, kök dışına veya ortak klasöre taşıma reddedilir; hata halinde taşımalar geri alınır. Diskte bulunmayan klasörlerin yalnızca kayıtlı adları hazırlanır; eksik belge varmış gibi oluşturulmaz. Aynı klasöre bağlı birden fazla kayıt veya diskte belirsiz eşleşme varsa kopyalama durur ve uyarı verilir; asıl belge MEDIA_ROOT'ta kalır. Klasör adları kayıt kilidiyle atanır; dosya kopyalarken aynı anda gelen yüklemeler de üzerine yazamaz, `(2)` eklenir. Elle klasör adı değiştirilirse eski klasör taşınmaz, yeni belgeler yeni ada gider.
- `apps/search`: global arama (üst çubuk canlı açılır liste + `/ara/` sonuç sayfası; Ctrl+K). Müvekkil/karşı taraf `search_key` (fold) ile, diğer alanlar `__unaccent__icontains` ile; müvekkilde sonuç yoksa `TrigramWordSimilarity` (> 0.45) ile yazım hatası toleransı. Muhasebe kayıtları aranmaz. Sonuç sayfasında tür sekmeleri (sayılarla; `?tur=muvekkil|dosya|gorev|karsi|belge`) ve sıralama (`?sirala=alaka|ad|yeni|eski`) vardır, HTMX ile `_results_body.html` yenilenir. "Tümü" sekmesinde her türden ilk 10 sonuç ve "tümünü gör" bağlantısı; tür sekmesinde tüm sonuçlar kullanıcının sayfa boyutuyla sayfalanır.
- `apps/activity`: auditlog kayıtlarının ekranı (`/aktivite/`; yönetici herkesi, diğerleri kendini görür; kullanıcı/tür/işlem/tarih filtresi). Giriş/çıkış `LogEntry.Action.ACCESS` olarak yazılır (`signals.py`). `User` değişiklikleri parola/son giriş/tema/liste boyutu hariç kaydedilir. Müvekkil ve dosya detayında "Geçmiş" sekmesi (`history_for`).
- `apps/reports`: 7 rapor (`definitions.REPORTS`: parametre formu + `build()` → `ReportResult`); önizleme HTML, `renderers.to_xlsx` (openpyxl) ve `to_pdf` (ReportLab, `reports/fonts/` altında gömülü DejaVu Sans — Türkçe karakter için). Finansal raporlar (`financial: True`) bakiye görme yetkisi (`can_view_balances`) ister.
- `apps/backups`: `manage.py backup [--scheduled|--update]` = `pg_dump -Fc` + MEDIA_ROOT → AES-256 şifreli ZIP (`pyzipper`, parola `BACKUP_PASSWORD`) → `BACKUP_DIR`; ayrıca `OfficeSettings.backup_dir`'e (bulut senkron klasörü) kopya. Saklama: son 30 günün günlük + son 12 ayın ilk yedeği (`apply_retention`, yalnızca `ozkurt-yedek-*.zip` dosyalarına dokunur). Görev Zamanlayıcı 30 dakikada bir `backup --scheduled` çalıştırır; bugün başarılı yedek yoksa ve `backup_time` geçtiyse yedekler (PC o saatte kapalıysa açılınca alınır). `manage.py restore <zip> --yes` (servis durdurulmuşken; mevcut media `media.onceki-…` olarak saklanır). `BackupRecord` geçmişi Ayarlar > Yedekleme'de; yöneticiye 2 günden eski yedekte uyarı bandı. Dev ortamında pg_dump host'ta yok: `PG_DUMP="docker exec -i ozkurt-hukuk-db-1 pg_dump"`, `PG_RESTORE=...pg_restore`, `BACKUP_DATABASE_URL=postgresql://ozkurt:<dev parola>@localhost:5432/ozkurt`.
- Yüklenen dosyalar `/media/` altında `core/media.protected_media` ile sunulur: yol öneki kayda göre yetki (ledger/ → muhasebe görme yetkisi; office/ logo girişsiz; tanınmayan yol ve kayda bağlı olmayan dosya 404). PDF/resim tarayıcıda, diğerleri indirme; `nosniff` ve PDF dışı türlerde sandbox CSP. Yükleme türleri `core/uploads.py` (izinli liste; .udf dahil; HTML/SVG/çalıştırılabilir reddedilir).
- Oturum güvenliği (`accounts/middleware.py`): `User.must_change_pin` olan kullanıcı PIN'ini değiştirene kadar yalnızca Ayarlar > PIN'e erişir (HTMX'te `HX-Redirect`). Yalnızca yönetici başkasına PIN verdiğinde işaretlenir; `setup_office_users` ortak başlangıç PIN'i atar, değiştirmek isteğe bağlıdır; yeni PIN eskisiyle aynı olamaz. `OfficeSettings.idle_minutes` (varsayılan 30, 0 = kapalı) kadar istek gelmeyen oturum kapanır, giriş ekranı `?zaman_asimi=1` notu gösterir; tarayıcıdaki küçük betik süre dolunca sayfayı yeniler. Girişli kullanıcıya giden yanıtlar `NoStoreMiddleware` ile `no-store` alır, `base.html` geri/ileri tuşuyla bellekten açılan sayfayı yeniler; çıkıştan sonra geri tuşu eski sayfayı göstermez. Ofis içi bağlantı HTTP'dir (HTTPS kurulmadı).
- Ayarlar > Kullanıcılar: yönetici kullanıcı ekler/düzenler/pasife alır, PIN sıfırlar (`UserAdminForm`; kullanıcı adı ad-soyaddan üretilir; kendi hesabını pasife alamaz/yöneticiliğini kaldıramaz).
- Sistem içi bildirim (zil) ve otomatik bildirim taraması kullanıcı kararıyla kaldırıldı (`apps/notifications` yok). Görev durumları ana sayfadaki rozetlerle izlenir.
- Tüm kullanıcı view'ları `LoginRequiredMiddleware` ile korunur. `/media/` de giriş ister.
- Aktivite kaydı `django-auditlog`; her app `ready()` içinde kendi modellerini kaydeder.

- Duruşma, dosyadaki karşı taraf bağlantısı ve müvekkil alt kayıtlarını yalnızca yönetici silebilir; düğmeler de aynı kurala bağlıdır.

- Excel raporlarındaki bütün metinler açıkça metin hücresi olarak yazılır. Uyarı ve hata mesajları kullanıcı kapatana kadar görünür kalır; başarı mesajı kısa sürede kapanır.
- Yedek dosyalarını dışlayan kural yalnızca kökteki `/backups/` içindir; `apps/backups/` uygulama kodu ve şema dosyaları ortak proje kaydına dahildir.
- Geri yükleme önce belgeleri aynı diskte geçici klasöre hazırlar. Veritabanı `pg_restore --single-transaction --exit-on-error` ile yüklenir; hata halinde eski belge klasörü geri konur. Başarılı dönüşte eski belgeler `media.onceki-...` altında saklanır. Windows yardımcısı güvenlik yedeği veya servis durdurma başarısızsa başlamaz; geri yükleme hatasında uygulamayı kapalı tutar. Gerçek yedek ve kurulu Windows servisleriyle dönüş provası hâlâ gereklidir.

## İş kuralları
- Her görev bir dosyaya, her dosya bir müvekkile bağlıdır. Görevde müvekkil dosyadan otomatik gelir.
- Her müvekkilin bir sorumlu avukatı (rol admin veya lawyer) ve bir sorumlu stajyeri (rol intern) vardır. Dosyada bunlar müvekkilden varsayılan gelir, değiştirilebilir.
- Herkes tüm kayıtları görür. Silme yalnızca yönetici. Belgeyi yükleyen veya yönetici siler. Muhasebe kaydını herkes görür ve girer; bakiyeleri yalnızca yönetici ve seçtiği kişiler görür.
- Her dosyada Konu zorunludur. Sözleşme (`consultancy`) ve Diğer türlerinde kurum/numara alanları görünmez; dosya adı konudur. Diğer türlerde Kurum Adı ve Dosya Numarası bu sırayla girilir; `Case.display_name` bunları `Kurum Adı - Dosya Numarası` biçiminde gösterir. Konu ayrı saklanır. Ekranlar, seçim alanları ve raporlar dosya adı için bu özelliği kullanır. Müvekkil zorunludur; sorumlu avukat/stajyer müvekkilden gelir ve değiştirilebilir.
- Kurum adı Türkçe kurallarla büyük harf kaydedilir; eski kurum adları da dönüştürülmüştür. Dosya numarası formda yıl (`official_year`, yeni kayıtta güncel yıl) ve pozitif sayısal numara (`official_sequence`) olarak girilir; mevcut `Case.official_no` alanında `yıl/numara` olarak tutulur. Eski biçime uymayan numaralar değiştirilmeden saklanır; düzenleme formunda eski değer açıklama olarak gösterilir ve geçerli iki parçayla girilmesi istenir.
- Dosya formunun Taraflar bölümünde müvekkilin sıfatı (`Case.client_role`), mevcut diğer tarafların sıfatları ve yeni taraf satırları birlikte bulunur. Dokuz türe göre sıfat listeleri `cases/party_roles.py` içindedir; form ve taraf ekleme işlemi sunucuda da bu listeyi doğrular. Eski kayıttaki artık listede olmayan sıfat, dosya türü değişmediyse düzenlemede korunabilir. Yeni satırlarda aynı TCKN/VKN mevcut taraf kaydını kullanır; paylaşılan taraf bilgileri üzerine yazılmaz. Dosya ve eklenen taraflar birlikte kaydedilir; hata varsa hiçbiri yazılmaz. Mevcut tarafı dosyadan çıkarma yalnızca yöneticidedir; formdaki çıkarma kutusu yalnızca henüz kaydedilmemiş yeni satırı yok sayar.
- Dosya formunda kurum ve yıl/numara girişleri tek etiket yüksekliğinde hizalanır. Notlar, iki sütunlu bölümün dışında ve kaydetme çubuğunun hemen üstünde tam genişliktedir. Taraf ekleme ve sıfat yenileme sırasında alanlar Alpine `$root` üzerinden bulunur; `$el` tıklanan düğme olabileceği için form alanlarını aramakta kullanılmaz. Düğmenin satır ekleme denemeleri `tests/js/case_form.test.cjs` içindedir; pytest bunları Node.js varsa çalıştırır, yoksa bu denemeyi atlar.
- Çok müvekkilli dosya: asıl müvekkil `Case.client`, diğerleri `Case.co_clients` (`CaseCoClient`: müvekkil + kendi sıfatı; dosya formunda "Müvekkil ekle" ile asıl müvekkil gibi satır eklenir, Taraflar'da sıfatına göre ilgili yanda "(müvekkil)" olarak listelenir). Dosya her müvekkilin sayfasında, listede (+N müvekkil), süzgeçte ve aramada görünür. Muhasebe hareketi hangi müvekkile kaydedilirse onda durur (`LedgerEntry.client`; müvekkil dosyanın müvekkillerinden değilse asıl müvekkile düşer); muhasebe hareketi olan ek müvekkil dosyadan çıkarılamaz. Klasör yapısı ve WhatsApp hatırlatmaları yalnızca asıl müvekkili kullanır.
- Numara gösterimi: dosya numarasının sonuna türüne göre ekranda otomatik "Esas" (hukuk/ceza/idari), "İcra", "Soruşturma" veya "Arabuluculuk"; karar numarasının sonuna "Karar" gelir (`Case.official_no_display`, `decision_no_display`, `display_name`). Yalnızca yıl/numara biçimindeki numaralara eklenir; saklanan değer değişmez, eski biçimli numaralar olduğu gibi gösterilir.
- Dosya durumu: `Case.status` yalnızca Açık/Kapalı; yeni dosya Açık ve türün ilk aşamasıyla açılır. Aşamalar ve kapanma nedenleri türe göre `apps/cases/stages.py` içindedir (kaynak: `aşamalar.txt`; anahtarlar sabit kalmalı). Kapalı dosyada `closing_reason`; kapanışta kapanış tarihi, not ("Diğer" nedeninde zorunlu), hukuk/ceza/idarede karar tarihi ve yıl/numara biçiminde karar no sorulur. İcra dışındaki türlerde tahsil/ödeme içeren nedenlerde tutar + tarih + "muhasebeye kaydedildi mi?" bilgisi yalnızca bilgi amaçlıdır. İcra kapanışında `CollectionFormSet` ile en çok 100 isteğe bağlı tahsilat satırı (tutar, tarih, açıklama) girilir; boş/silinen satırlar yazılmaz, kısmi/hatalı satır kapanışı durdurur. Tahsilatlar `close_case` işlemi içinde asıl müvekkile `TRUST_IN` olarak `create_entry` ile yazılır; `LedgerEntry.closing_event` aynı kapanışın hareketlerini ilişkilendirir. Muhasebe ve kapanış tek işlemde geri alınır; dosya kilidi tekrarlı kapanışta çift kayıt oluşmasını önler. İcra ekranında eski muhasebe sorusu/uyarısı yoktur; tarih kapanıştan sonra olamaz. Önceden girilen kayıtlar kendiliğinden muhasebeye aktarılmaz; yeniden açma mevcut muhasebe hareketlerini silmez. Aşama değişimi ve kapatma `cases/services.py` üzerinden yürür (kilit + olay kaydı); yeniden açma yalnızca yönetici. Detayda solda AÇIK/KAPALI, sağda aşama çizgisi (tıklayınca onay) veya kapanış bilgisi görünür. Dosya türü renkleri CSS'te `.type-<tür>` sınıflarıyla tanımlıdır (liste satırı, tür etiketi, süzgeç düğmeleri, detay ikonu); liste süzgeçleri Açık/Kapalı/Tümü ve tür düğmeleridir (radio + HTMX). Listede sütunlar: fiziki arşiv no, dosya türü, durum, AŞAMA, dosya bilgisi, müvekkil, açık görev, sorumlular, açılış tarihi. Aşama süzgeci `stage=<tür>:<aşama>` biçimindedir; türler aynı aşama anahtarını kullansa da karışmaz. Kapalı dosyalarda aşama boş, kapanma nedeni durumun altında gösterilir.
- Safahat (bağlı dosyalar): safahat "aşama" kaydı değildir; her aşama (ihtarname, arabuluculuk, ilk derece, istinaf, icra vb.) ayrı bir dosyadır ve aynı hukuki olaya ait dosyalar bağlanır (kullanıcı kararı; `CaseStep` ve karar türü listesi kaldırıldı, `cases/0019`). Bağlı dosyalar `Case.flow` (`CaseFlow`) ile gruplanır, zincir bağlantılar tek grupta toplanır; bağlanacak dosyaların en az bir ortak müvekkili olmalıdır (`services.link_cases`). Dosya detayındaki Safahat sekmesinde "İlgili dosya oluştur" (`cases:create?iliskili=<pk>`: müvekkil, ek müvekkiller, müvekkil sıfatı, taraflar (aynı `Party` kaydı kullanılır), fiziki arşiv yeri, sorumlu avukat/stajyer ve konu önceden dolar, kayıtla birlikte bağlanır) ve "İlgili dosya bağla" (mevcut dosya + isteğe bağlı not `Case.flow_note`) vardır. Akış tek listedir; her dosyanın başında AÇIK/KAPALI, dosya türü ve açıksa aşaması/kapalıysa kapanma nedeni görünür; sıra `Case.flow_position` ile tutulur (yeni dosya sona eklenir, yukarı/aşağı oklarıyla onay sorularak değişir). "Bağlantıyı kopar" (`unlink_case`; tek dosya kalırsa grup dağılır, dosya silinmez) yetkisi yönetici ve avukatlardadır. Ortak olanlar yalnızca safahat ve muhasebedir: bağlı dosyalarda her birinin Muhasebe sekmesi grubun tüm hareketlerini ve ortak (toplam) bakiyeyi gösterir (Dosya ve gerekirse Müvekkil sütunuyla); müvekkilin kendi sayfasında yalnızca kendisine yazılan hareketler görünür. Liste, müvekkil dosyalar tablosu ve raporlarda bağlı dosyalar art arda ve bağ işaretiyle gösterilir, adın yanında "+X dosya bağlı" etiketi çıkar (`apps/cases/flows.py: cluster`; kümeleme yalnızca gösterilen sayfa/liste içinde yapılır).
- Dosya formunda durum, aşama ve kapanış alanları yoktur (detaydan yönetilir); değer alanı da formda yoktur, mevcut kayıtların değeri korunur. Dosya açılış tarihi zorunludur; yeni kayıtta `timezone.localdate` ile güncel gün gelir, düzenlemede eski tarih korunur. Gizlenen eski kurum/numara bilgileri silinmez.
- Excel aktarımının mevcut tek arşiv alanı, klasör numarası boş kayıtlara karşı denetlenir; iki alanlı yeni aktarım şablonu aktarım adımında ele alınacaktır.
- Fiziki arşiv yeri klasör no (`Case.archive_folder_no`) ve dosya no (`Case.archive_no`) olarak tutulur; ikisinin birleşimi büyük/küçük harf duyarsız tekil olmalıdır — veritabanı kısıtı kaldırıldı, form denetler ve yalnızca bağlı (ortak safahatlı) dosyalar aynı fiziki yeri paylaşabilir. `archive_reference` ekranlarda ve çıktılarda birleşik yeri gösterir. Eski arşiv numaraları dosya no olarak korunur; eski kayıtta klasör no sonradan doldurulabilir. Yeni dosyada iki alan da zorunludur; otomatik arşiv numarası önerilmez.

Onaylanan görev Aktif duruma "Onaylandı" aşamasıyla sorumluya döner; kapatma işlemi ve bilgileri kullanıcıyla ayrıca tasarlanacak, henüz kapatma düğmesi yok. Revizyon isteği Aktif'e döner; yeniden gönderilince Kontrolde "Revize Edildi" görünür. Yeni görev sorumlu açana kadar "Yeni Görev" görünür. Onayda belgeler yayınlanır, görevin onaylandığı olay kaydedilir; onaylanan görev kapatma tasarlanana kadar düzenlenemez veya yeniden gönderilemez. Eski tamamlanmış kayıtlar Kapalı olarak korunur.
- Görev türleri `GOREVTURLER.txt` listesinden alınmıştır (`office/0008-0009`); aynı ad ve puanlı tekrarlar tek türdür, önceki türler silinmeden pasife alınmıştır. Tür puanları Ayarlar > Görev türleri ekranından yönetilir; yeni görevde tür seçimi adı doldurur, Diğer seçilirse kullanıcı yazar. Otomatik haciz yenileme görevi "Haciz Yenileme Talebi" türündedir.

Eski "Ofis İçi, Araştırma ve Diğer İşlemler" adı ekranda "Ofis İçi İşlemler" olarak gösterilir. Tür veya kategori adı yazılarak aranır; kategorisiz eski/elle eklenmiş türler "Diğer görevler" altındadır.
- Görev türü adlarında kelime başları Türkçe kurallarla büyük yazılır; diğer harfler ve kısaltmalar korunur (`tr_capitalize_words`, `office/0012`). Yeni veya düzenlenen türlerde de aynı kural geçerlidir.
- Görev oluşturulurken isteğe bağlı bir belge yüklenebilir. Görev belgeleri asıl depoda tutulur ve dosyanın ofis klasöründeki `Görevler` alt klasörüne kopyalanır (`TaskDocument.folder_path`, `tasks/0008`); klasör ayarsız veya erişilemezse belge saklanır ve uyarı gösterilir. Sonradan yüklenen sürümler de aynı klasöre kopyalanır, ad çakışmaları numaralandırılır. Onayda güncel sürüm ayrıca dosyanın Belgeler bölümüne yayınlanır. Klasörleri yeniden adlandırma komutu görev belgesi kopyalarının yollarını da günceller.
- Puan altyapısı: `TaskPoint` görev ve kullanıcı başına tek kayıtta puan ve kazanılma zamanını saklar; Ayarlar > Personel puanları yalnızca yöneticiye toplam, içinde bulunulan hafta ve ayı gösterir. `award_closed_task_points` kapalı görev için sorumluya ve kontrolcüye puanı birer kez kaydeder; eski görevlere puan aktarılmaz. **Henüz tamamlanmadı:** görev kapatma işlemi tasarlanmadığından bu yardımcı hiçbir işlemden çağrılmıyor ve yeni puanlar henüz kazanılmıyor. Kapatma işlemi oluşturulunca aynı veritabanı işlemi içinde çağrılıp yeniden açma/silme davranışı da kullanıcıyla kararlaştırılmalı.
- Muhasebe (TL, vergi yok): **Müvekkilin ofise borcu** = vekalet ücreti + masraf. **Müvekkilin ofisten alacağı** = karşı taraftan tahsilat. **Bakiye tutar** = (müvekkilin ofise borcu − müvekkilden tahsilat) − karşı taraftan tahsilat + müvekkile ödeme (pozitif: müvekkil ofise borçlu; negatif: ofis müvekkile borçlu). Hareket silinmez, iptal edilir.

Hatalı satır varsa hiçbir şey yazılmaz. Ofisin kendi Excel formatı görülünce şablon ona göre uyarlanabilir.

## Görev, muhasebe ve rapor ekranları
- Görev listesinde Bana atanmış/Tümü kapsamı ve Aktif görevlerim, Kontrolümü bekleyenler, Kontrolde olanlar, Kapalı görevler sekmeleri bulunur. Kişisel görünümde ilk ve üçüncü sekme sorumluya, ikinci sekme kontrolcüye; kapalı sekmesi iki role göre süzülür. Tümü kapsamında kontrol bekleyenler ve kontrolde olanlar tüm kontroldeki görevleri gösterir. `sorumlu`, `kontrolcu`, `son_gun` ve `sort` süzgeçleri korunur; son gün süzgeci kapalı görevlere uygulanmaz.
- Görev formu `.form-masonry` ile iki sütuna dengelenir. Görev ayrıntısında Belgeler, Yorumlar ve Geçmiş ayrı sekmelerdir; yorum ekleme dönüşü `#gecmis` yorum sekmesini açar. Revizyon gibi işlem açıklamaları işlem geçmişinde korunur; yorumlar yalnızca yorum sekmesindedir. Yetki ve onay döngüsü değişmemiştir.
- Muhasebe listesinde `q` açıklama/müvekkil/dosya arar; `musteri`, `dosya`, `tur`, tarih ve `durum=active|cancelled|all` süzgeçleri ile güvenli `SORT_OPTIONS` sıralaması vardır. Eski `iptal=1` bağlantıları tüm kayıtları göstermeye devam eder. Müvekkil ve dosya ayrı sütunlardır; iptal nedeni/kişi/zaman gösterilir. Özetler süzülmüş kayıtlardan hesaplanır, iptaller hesaba girmez ve yalnızca bakiye yetkilisine gönderilir. Form aynı iki sütun düzenini kullanır.
- Raporlar `REPORT_GROUPS` ile Dosya/Görev/Mali gruplarına ayrılır; mali grup yine bakiye yetkisine bağlıdır. Rapor tarih aralığında başlangıç bitişten sonra olamaz. Dosya raporlarında aşama/kapanma nedeni, aktif haciz sayısı ve en erken yenileme tarihi bulunur; alt sorgularla hazırlanır. Dosya listesi raporunda türle birlikte aşama süzgeci vardır.
- `haciz-takibi` raporu müvekkil, avukat, aktif/pasif haciz, yenileme tarih aralığı ve kapalı dosya seçimine göre borçlu/mal varlığı/tarih/sorumlu/kontrolcü/görev durumunu gösterir. Dönem ölçütü yenileme tarihidir. Önizleme ve Excel/PDF aynı `ReportResult` sütunlarını/sırasını kullanır; önizleme genişlikleri aynı sütun ağırlıklarından hesaplanır. Excel metinleri açıkça metin olarak yazılmaya devam eder.

## Haciz takibi
- İcra dosyasında takip türü yanında isteğe bağlı serbest metin dayanak ve takipte kesinleşen miktar tutulur; bu bilgiler özette ve İcra takibi sekmesinde gösterilir. Haciz türleri tek kartta ayrı bölümler ve her türün kendi ekleme bağlantısıyla gösterilir; eski türsüz kayıtlar ayrı bölümde korunur. Şema: `cases/0026`.
- Yalnızca açık icra dosyalarında Haciz takibi sekmesinden `Seizure` kaydı eklenir/düzenlenir. Borçlu, aynı dosyanın `debtor` sıfatlı tarafları arasından seçilir: `CaseParty` üzerinden Party veya asıl/ek müvekkil. `debtor_party`/`debtor_client` ilişkilerinden en çok biri doludur; `debtor` adın kopyasını korur. Kayıt anında güncel taraf listesi yeniden doğrulanır. Borçlu yoksa Taraflar sekmesine yönlendiren açıklama gösterilir.
- Türler/aşamalar `apps/cases/seizure_types.py` içindedir: Maaş, Banka Hesabı, Araç, Tapu, Alacaklı Olduğu İcra Dosyası, Mahal ve 89/1-2-3 Haczi. Seçilen türe göre durum ve ayrıntı alanları açılır. Her banka ve plaka ayrı kayıttır; virgülle girilen banka adları aynı işlemde ayrı kaydedilir. Bankada banka adı, araçta tek plaka, tapu varsa taşınmaz, mahalde adres, alacaklı dosya varsa kurum/numara zorunludur. 89 tek kayıttır: ihbarname (89/1, 89/2, 89/3) ve talep/itiraz geldi/gelmedi ayrı tutulur. Maaşta işveren isteğe bağlıdır.
- Haciz olmayan aşamalarda haciz/yenileme tarihi istenmez. Maaş sıraya alındı/uygulanıyor, bankaya haciz/para isteme, araç, tapu, adreste haciz ve alacaklı olunan dosyaya haciz aşamalarında haciz tarihi zorunludur. Araç/tapuda kullanıcı tercihi olarak bir takvim yılı sonrasından 30 gün önce yenileme önerilir (29 Şubat sonraki yıl 28 Şubat üzerinden hesaplanır); elle girilen tarih korunur. Bu bir hukuki süre hesabı değildir. Alacaklı olunan icra dosyasında yenileme gerekiyorsa tarih elle girilir. Yenileme tarihi hacizden önce olamaz; diğer türlerde yenileme görevi oluşturulmaz. Açık dosyada haciz kaydını yalnızca yönetici silebilir; oluşturulmuş görevler korunur. Kapalı dosyada kayıtlar salt okunur.
- Eski serbest metinli kayıtlar `kind` boş olarak korunur ve önceki yenileme takibini sürdürür. Düzenlerken borçlu/tür/aşama seçilir; önceki `asset` metni silinmez ve formda bilgi olarak gösterilir. Olumsuz tespitler (Araç Yok vb.) raporlardaki aktif haciz sayısına dahil edilmez; haciz takip raporunda tür/ayrıntı/aşama görünür. Haciz tarihi ve yenilemesi olmayan kayıtlarda boş tarih gösterilir.
- `apps/cases/seizures.py:create_due_tasks` aktif haczin tarihi geldiğinde/geçtiğinde açık icra dosyasının güncel sorumlu stajyerine, kontrolü sorumlu avukatına `Haciz yenileme` türünde görev oluşturur. Son gün özgün yenileme tarihidir; bilgisayar kapalı kaldıysa ilk çalışmada yetişir. Pasif sorumlular varsa görev oluşturulmaz ve komut sayısıyla/ekran uyarısıyla bildirilir.
- `SeizureRenewal` haciz + tarih birleşimini tekil tutar. Dosya ve haciz satırı kilitlenir; görev ve iz kaydı aynı işlemde yazılır. Aynı tarihte görev silinse bile tekrar oluşturulmaz. Yenileme tarihi değiştirilince önceki görev/geçmiş korunur; yeni tarih için yeni döngü başlar.
- Bir defalık kontrol: `uv run python manage.py create_seizure_tasks`. Yerel sunucuda sürekli kontrol: aynı komut `--watch` ile dakikada bir; açık oturum isteğinde de `SeizureTaskMiddleware` en fazla dakikada bir kontrol yapar. Kurulum/güncelleme `Ozkurt Hukuk Haciz Takibi` Windows görevini başlangıçta ve beş dakikada bir çalıştırır; yardımcı `check-reminders.ps1` yalnızca `create_seizure_tasks` çağırır, servis kapalıyken atlar. Geri yükleme/kaldırma bu görevi de durdurur/kaldırır. Kurulum paketi yenilenmeden kurulu ofis sunucusunda görev kendiliğinden eklenmez.
- Şema: `cases/0024`, `cases/0025`, `accounting/0003`. Haciz ve yenileme modelleri aktivite kaydına dahildir. Denemelerde yalnızca uydurma veri kullanılır.
